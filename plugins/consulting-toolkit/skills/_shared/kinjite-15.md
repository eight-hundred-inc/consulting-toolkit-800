# PowerPoint「15 の禁じ手」— HTML → PPTX パイプラインでの適用

## なぜ守るのか（原典の 3 要件）

禁じ手はすべて、資料作成に求められる次の 3 つを壊す打ち方として定義されている。

1. **スピーディな作成** — 作成に時間がかかる打ち方
2. **修正の容易性** — 後で修正・流用するのが面倒な打ち方
3. **見易さ・わかり易さ** — アウトプットが見苦しくなる打ち方

HTML デッキでは、ここに **4 つ目：変換に耐えること**（実 DOM の矩形・単色・文字だけで意味が伝わること）が加わる。禁じ手の多くが `references/pptx-safe.md` の規約と同じ結論に着地するのはこのためで、**原典の禁じ手と PPTX 変換セーフ規約は矛盾しない**。

|---|---|---|
| **A. HTML 作成時に完結**（html-artifact / slide-pattern-creator） | ② 改行＆スペース多用<br>③ 箇条書きの点直打ち<br>④ スペース・インデント<br>⑤ モノ文字ボックス<br>⑥ バラバラフォント<br>⑦ 下線直書き<br>⑧ 行間ピッタリ<br>⑪ サイズバラバラ<br>⑫ 縦横配置バラバラ<br>⑬ 線でマトリックス<br>⑭ アニメーション<br>⑮ 3 軸グラフ | HTML を書いた時点で決まる。変換器は実測した矩形・文字をそのまま pptx にするので、**HTML で崩れているものは pptx でも必ず崩れる**。変換側では直せない |
| **B. 変換時に決まる**（html-to-deck） | ① タイトル＆メッセージ直打ち（マスター継承） | どのテンプレート pptx を渡すか、タイトル／メッセージがマスターのプレースホルダに載るかは変換の入力と結果で決まる。HTML 側は「全スライドで同じ位置・同じ構造にしておく」ことしかできない |
| **C. 組み合わせて対応**（HTML の書き方 × 変換結果の確認） | ① マスター継承の確認<br>③ 箇条書きの段落化<br>④ ぶら下げインデント<br>⑨ 図形に文字ボックス<br>⑩ 図形間の線が"ただ"の線 | HTML 側が「変換器がそう解釈できる形」で書き、**変換後に report.md で実際にそうなったかを確認**して初めて成立する。ずれていたら HTML を直して `--rebuild` する（pptx 側をいじっても直らない） |

## ① タイトル＆メッセージ直打ち

**原義**：スライドマスターを使わず、各スライドに文字ボックスを貼ってタイトル／メッセージを書く。位置合わせに苦労し、他ファイルとマージするときに余計な労力がかかる。

| レイヤー | やること |
|---|---|
| **A. HTML** | タイトル行・メッセージ行は**統一シャシの固定クラス**（`.slide-title` / `.slide-msg` 等）で書き、**全スライドで同一の DOM 構造・同一の CSS**（`:root` 由来のトークン）にする。スライド固有の `style=""` で位置・サイズを上書きしない。テンプレート（`assets/template-slides.html`）のフレームを複製して使い、スライドごとに作り直さない |
| **B. 変換** | タイトル／メッセージのプレースホルダを持つテンプレート pptx を渡す。テンプレートのテーマ・マスターは変換で継承される |
| **C. 確認** | 変換後、全スライドのタイトル行・メッセージ行が**同じ座標・同じサイズ**で出ているかを report.md で確認する。1 枚だけずれていれば、その枚の HTML に個別の上書きが混じっている。HTML を直して `--rebuild` |

**判定**：スライドごとにタイトル行の CSS が違う ＝ 禁じ手。

## ② 改行＆スペース多用

**原義**：文章の幅を合わせるためだけに改行とスペースを使う。後で枠を縮めると右端が段々になる。

- **`<br>` で行幅を調整しない**。折り返しは要素の幅と `line-height` に任せる
- **`&nbsp;`・全角スペースで字下げ・幅調整・位置合わせをしない**（区切り記号の前後に置く `&nbsp;·&nbsp;` のような**意味のある非改行スペース**は対象外）
- `<br>` を使ってよいのは、**意味として 2 行に分けたい行**だけ（カバーのサブタイトル、カード内で語のまとまりを保つ 2 行、図解ラベルの意図的な改行）。この用途は `pptx-safe.md` §2 の「本文のテキストノードを直接持つ」書き方と併用する
- 幅が足りずに崩れるなら、改行ではなく**文字数を減らす**（`pptx-safe.md` §5 の 9 割ルール）

**担当**：A（HTML 作成時に完結）。

## ③ 箇条書きの"点"直打ち

**原義**：箇条書きの点を行頭文字機能で出さず、「・」を直接打つ。修正・変更が効かなくなる。

原典は PowerPoint の操作を指すが、HTML では「**リストをリストとして書いているか**」が対応物になる。

| レイヤー | やること |
|---|---|
| **A. HTML** | 箇条書きは必ず **`<ul>` / `<ol>` ＋ `<li>`** で書く。`<p>` や `<div>` を並べて箇条書きに「見せる」のは禁じ手（構造が失われ、項目の追加・並べ替えができない）。マーカー字形は `::before` ではなく**行のテキストノード**に置き（`<li>● …</li>`）、字下げは `padding-left`＋負の `text-indent` で作る（`pptx-safe.md` §1。変換器は疑似要素を実測できないため） |
| **C. 確認** | 変換後に各項目が**独立した段落**になっているかを確認する。1 項目が 2 段落に割れていれば `pptx-safe.md` §2（1 行を複数要素に分けない）違反。行頭の `●` が段落の行頭文字ではなくテキストの一部として出ている場合は、**引き渡し時に「PowerPoint 側で段落の行頭文字に置き換えると以後の編集が楽」と申し送る**（変換器の仕様であり HTML 側の誤りではない） |

**要注意（矛盾に見える点）**：原典は「・を打つな」、pptx-safe は「マーカーを行テキストに書け」。守るべき本質は **`<ul>/<li>` の構造を捨てないこと**で、字形をどこに置くかは変換器の実測仕様に合わせる。構造さえ残っていれば、修正の容易性（要件 2）は保たれる。

## ④ スペース・インデント

**原義**：箇条書きの行頭を揃えるためにスペースを使う。インデント機能を使うべき。

- 字下げは **`padding-left`＋負の `text-indent`**（`margin-left` は箱ごとずれ、罫線・背景が本文左端からずれる。`pptx-safe.md` §1）
- スペース・全角スペース・`&nbsp;` の連打で行頭を揃えない
- **C. 組み合わせ**：`text-indent` は pptx に引き継がれない。**折り返し行が左端に戻っても意味が壊れない字面**にしておき、ぶら下げが必要な箇所は引き渡し時に「PowerPoint 側の段落インデントで揃える」と申し送る

**担当**：A（書き方）＋ C（変換後の申し送り）。

## ⑤ モノ・文字ボックス

**原義**：ひとつの文字ボックスにすべての文章を詰め込む。融通が利かない。文章の塊ごとにボックスを分け、ただし横幅は揃える。

- **意味の塊ごとに要素を分ける**。1 枚のスライドの本文全部を 1 つの `<div>` / `<p>` に流し込まない。ゾーン → カード → 段落の単位で要素を切る
- **分けた要素の横幅は揃える**（grid の `1fr`、または同一の `width`）。原典の「横幅はできるだけ揃えておく」に対応
- **⑤ と `pptx-safe.md` §2 を混同しない**：
  - **行の中は分けない**（`<span>✓</span><span>本文</span>` は NG。§2）
  - **塊と塊は分ける**（1 ボックスに全文流し込みは NG。⑤）
  - 判定軸＝「同じ 1 行か、別の意味の塊か」

**担当**：A（HTML 作成時に完結）。

## ⑥ バラバラフォント

**原義**：フォントの種類がバラバラ／「入りきらないから」という理由で文字サイズを縮める。英数字の字体・全半角も揃える。

- **書体**：`var(--font-jp)`（既定 Noto Sans JP、EightHundred テーマのみ Meiryo UI）と JetBrains Mono（数値・章番号・コード）以外を使わない
- **並列要素のサイズは揃える**：同じ役割の要素（カード本文、リスト項目、表セル、ゾーン見出し）は**デッキ全体で同一の `font-size`**。1 枚だけ・1 カードだけ小さくしない
- **「入り切らないから縮める」は禁じ手**。縮めるのではなく**情報量を減らす**か**スライドを分ける**（`_shared/slide-body-principles.md` 原則 5、`pptx-safe.md` §6 の 11px 下限）
- **同一ボックス・同一行内でのサイズ変更禁止**（`design-system.md`）。数値と単位も同一サイズにし、強弱は色・`font-weight`・余白で出す
- **英数字・カタカナの全角／半角を揃える**：英数字は半角、カタカナは全角に統一する（`ﾓﾃﾞﾙ` と `モデル`、`FY10` と `ＦＹ１０` の混在は禁じ手）。単位・記号（`%` `→` `・`）もデッキ内で表記を統一する
- **C. 組み合わせ**：PowerPoint のテーマフォントは Web フォントより字幅が 1〜2 割広い（`pptx-safe.md` §5）。変換後に 1 箱だけ文字が小さくなっている＝自動調整が効いた箇所なので、**HTML 側の文字数を減らして `--rebuild`**（pptx 側でサイズを戻すと禁じ手⑥そのものになる）

## ⑦ 下線直書き

**原義**：文字の下にだけ線を引くのに「直線」図形を引く。文章を変えると線も直す必要が出る。※ 文章幅より長い線は対象外。

HTML での「直線図形」に当たるのは、**絶対配置の線要素と疑似要素（`::after` の罫）**である。

- 語句の下線が必要なら **`text-decoration: underline`**（文字に従属するので文章を変えても追従する）。ただし html-artifact では語句強調は `<strong>` と `<mark>` が既定で、下線はほぼ使わない
- **線を「引く」ために要素を足さない**。区切りは**その要素自身の `border-top` / `border-bottom`** で出す（要素に従属するので内容が変わっても追従する）。`position:absolute` の細い `div`・`::before`/`::after` の罫は使わない（`pptx-safe.md` §1）
- **区切りの罫線（文章幅より長い線）は禁じ手の対象外**（原典：「文章幅より長く下線を引く場合については当てはまらない」）。章見出し下・小見出し下・項目の区切り罫は従来どおり要素の border で引いてよい
- **PPTX 変換セーフモードのときだけ追加制約**：**行ごとのアンダーライン（`li` の `border-bottom`）は外す**。pptx では行が個別図形になり、テーマフォントの折り返し差で線の長さ・位置が行ごとにばらつくため、項目の区切りは**行間**で表現する（`pptx-safe.md` §1）。ブラウザ投影で完結する Vertical Document / デッキではこの制約は不要

**担当**：A（HTML 作成時に完結）。

## ⑧ 行間ピッタリ

**原義**：行間をすべて 0 にして文章をくっつける。段落と段落の間は広めに取らないと見にくい。

- **`line-height` の下限を守る**：見出し 1.4〜1.5／本文 1.85〜1.95（Slide Deck は 1.7〜1.8）／リスト 1.7〜1.85／表セル 1.7（`design-system.md`）。`line-height:1` / `1.2` を本文に使わない
- **段落・項目の間に余白を取る**：`li { margin-bottom }`、段落間 14px 相当。ゼロ詰めにしない
- 縦が足りないときに**行間を詰めて詰め込まない**。⑥ と同じく情報量を減らすかスライドを分ける（`_shared/slide-body-principles.md` 原則 7 は逆に「余りを間延びで埋めない」——**詰めるのも伸ばすのも禁じ手**で、換算表の値を保つ）
- **例外**：折り返さない単行の表示要素（Hero Number の巨大数値、図版内の 1〜2 語ラベル）は行間を詰めても段落がくっつかないため対象外。対象は「読ませる行」（本文・リスト・表セル・見出し）

**担当**：A（HTML 作成時に完結）。

## ⑨ 図形に文字ボックス

**原義**：図形の上に文字ボックスを貼って文字を書く。図形に直接書き込むのが基本。

| レイヤー | やること |
|---|---|
| **A. HTML** | 塗り・枠を持つ要素（カード、ノード、帯、セル）が、**そのテキストノードを直接持つ**（`pptx-safe.md` §2）。塗り div の上に `position:absolute` のテキストを重ねない。図解ノードもラベルを子要素に外出しせず、ノード自身に書く |
| **C. 確認** | 変換後に「塗り図形＋別テキストボックス」の 2 オブジェクトに分解されていないかを report.md で確認する。分解されていれば該当行が別要素に分かれている。HTML を直して `--rebuild` |

## ⑩ 図形間の線が"ただ"の線

**原義**：フローチャートの図形間を直線の組み合わせで描く。図形を動かすと引き直しになる。コネクタを使う。

| レイヤー | やること |
|---|---|
| **A. HTML** | 矢印・線は**結ぶ 2 つのノードの間に 1 本ずつ独立して置く**（独立した `<svg>` 1 つ、または `<div>` の border）。図版全体を覆う 1 枚のオーバーレイ `<svg>` に全部の線を描かない（`pptx-safe.md` §7）。CSS の三角形ハック・疑似要素の矢印も不可 |
| **B. 変換** | 1 本 1 本が独立していれば、変換器はこれを **pptx のコネクタ**（両端が図形にグルーされた線）に変換できる。オーバーレイ SVG は「1 枚の画像として貼る」か「線に分解する」かで揺れ、修正ループが収束しない |
| **C. 確認** | 変換後、図形を動かしたときに線が追従するか（＝コネクタになっているか）を確認する。ただの線に落ちていれば HTML 側の置き方を 1:1 に直して `--rebuild` |

**この項目は A 単独では完結しない**。HTML が「コネクタに解釈できる形」で置き、変換結果で実際にそうなったことを確認して初めて禁じ手を回避できる。

## ⑪ サイズバラバラ

**原義**：並列に並ぶ項目・見出しのハコや文字ボックスのサイズがバラバラ。見苦しく、修正しにくい。**塗りも枠も無色でもサイズは揃える**。

- 並列カードは **grid の `1fr`（等分）＋ `align-items: stretch`**（下端を揃える）。個別の `width` / `height` を px で微調整しない
- **見えない器もサイズを揃える**：背景・枠を持たないゾーンでも、幅・パディングは他の並列ゾーンと同じ値にする（原典の「塗りつぶしも枠線も無色でもサイズはそろえる」）。変換器は矩形を実測するため、**見えない不揃いも pptx では不揃いな図形になる**
- 並列ブロックの終端を揃える（`_shared/slide-body-principles.md` 原則 4・原則 8）

**担当**：A（HTML 作成時に完結。HTML でズレていれば pptx でも必ずズレる）。

## ⑫ 縦横配置バラバラ

**原義**：並列に並ぶハコ・文字ボックスの位置が縦横でずれている。配置／整列コマンドで揃える。

- レイアウトは **grid / flex で軸を揃える**。`position:absolute` ＋ px の微調整で並べない（作り込み図版の絶対配置キャンバスは例外だが、その中でも**座標値を共有トークン化**して揃える）
- **テキストの左端を揃える**：`margin:0` を基本にし、要素ごとに `margin-left` を足して見た目を合わせない（`pptx-safe.md` §1）
- ゾーンの上端・下端、カードのパディング、要素間ギャップをデッキ全体で一定にする

**担当**：A（HTML 作成時に完結）。

## ⑬ 線でマトリックス

**原義**：マトリクスを線で描く。ハコを組み合わせた方が早くきれいで、文字も書き込みやすい。

- **マトリクス・表・2x2 は「セル（面）」で組む**。`<table>` の `<td>`、または grid のセル `<div>` を並べる。罫線を引いた領域に絶対配置テキストを載せる作り方をしない
- 罫線は **セルの `border`** で引き、**表全体で色・太さ・実線/点線を統一**する（`pptx-safe.md` §9。セルごとに変えるほど pptx の図形数が線形に増える）。強調は `background-color` で出す
- 固定 8 図解の 2x2 マトリクス（`dgram-quad`）・Report Table はこの形で既に定義されている。新規に線で組み直さない

**担当**：A（HTML 作成時に完結）。

## ⑭ アニメーション

**原義**：オブジェクトにアニメーションを設定する。設定・管理に工数を取られ、印刷すると意味をなさない。

- **スライド本体（`section.slide` の中身）に `@keyframes` / `animation` / スクロール連動・出現エフェクトを使わない**
- `transition` は**プレゼンチャーム（カウンタ・サムネイル・操作ヒント・リンクのホバー）だけ**に許す。これらは印刷時に `display:none` になり、変換器の実測対象にも入らない UI レイヤーであるため、原典の禁則（印刷で意味をなさない／管理工数）には当たらない
- コンテンツの意味をアニメーションに預けない（段階的に出す説明は**スライドを分ける**）
- **変換時**：アニメーションは pptx に載らない。HTML で動きに頼っていた情報はそのまま消える

**担当**：A（HTML 作成時に完結）。

## ⑮ 3 軸グラフ

**原義**：x・y・z の 3 軸を使った立体グラフ。軸と比較対象が増えてメッセージが伝わらない。軸を分けるか、ピボットで処理する。

- **3D・立体のチャートを作らない**（`dataviz` スキルの方針とも一致）。奥行き・斜め投影・3D 円グラフ・積層した立体棒はすべて禁じ手
- 比較軸が 3 つある場合は、**軸を分けて複数のチャートに割る**（例：オフィス別にグラフを分ける）か、スライドを分ける
- **1 スライド 1 メッセージ**に戻して考える。1 枚のグラフで 3 軸を語ろうとしている時点で、メッセージが 2 つ以上ある
- 回転・斜め配置・浮遊要素の禁止（`design-system.md` 禁止パターン）と同根。変換器も 45 度以外の回転を実測できない

**担当**：A（構成・作図の段階で完結）。
