# _shared/pptx-templates — スキル横断の既定テンプレート pptx

複数スキルが**テンプレート指定を省略されたときの既定**として参照する pptx を置く。
1 スキルの配下に置くと他スキルからの参照が越境するため、共有資産としてここに集約している。

```
_shared/pptx-templates/
├── README.md
├── RONNABYTE.pptx        ← 既定テンプレート（RONNABYTE ブランド。中身は 800 版と同一構成）
└── テンプレート.pptx      ← 旧既定（800 の標準マスター。選択で切り替え可）
```

**2 本は同じデッキのブランド違い**（スライド 122 枚・セクション構成・パターン集が共通で、
配色／ロゴ／フッタだけが異なる）。どちらを選んでもレイアウトの当たり方は変わらない。

## テンプレートの選択

**2 本を共存させ、指定が無ければ `RONNABYTE.pptx` を使う。** 切り替えは次の 3 通り。

| 指定 | 使われるテンプレート | 備考 |
|---|---|---|
| 無指定 | `RONNABYTE.pptx` | 既定。尋ねない |
| `--template <path>`、パスの提示、「このテンプレートで」等 | 指定された pptx | **最優先**。既定は無視される |
| 「800 で」「エイトハンドレッドのテンプレートで」「旧テンプレートで」等のブランド名指定 | `テンプレート.pptx` | 下表のエイリアスで解決する |

**ブランド名エイリアス**（利用者がパスではなくブランド名で言った場合の解決表）：

| 利用者の言い方 | 解決先 |
|---|---|
| `ronnabyte` / RONNABYTE / ロナバイト / 新テンプレート | `RONNABYTE.pptx` |
| `800` / `eighthundred` / エイトハンドレッド / 旧テンプレート | `テンプレート.pptx` |

**html-artifact のテーマとの対応**：PPTX 変換セーフモードでは、
テーマ指定に合わせて既定テンプレートも揃える（ねじれを防ぐため）。

| html-artifact のテーマ | 既定テンプレート |
|---|---|
| RONNABYTE（既定） | `RONNABYTE.pptx` |
| EightHundred | `テンプレート.pptx` |
| その他 5 テーマ（Mono / Terracotta / Navy / Forest / Charcoal） | `RONNABYTE.pptx`（既定のまま） |

いずれの場合も、利用者が明示したテンプレートが常に優先する。

| スキル | 使い方 |

| [`html-artifact`](../../html-artifact/SKILL.md) | PPTX 変換セーフモードで生成する HTML の、想定変換先テンプレート |
| [`html-to-deck`](../../html-to-deck/SKILL.md) | `--template` 省略時の変換先テンプレート |

| [`pptx-from-reference`](../../pptx-from-reference/SKILL.md) | `reference-decks/` と併せて、既定で解析対象に含める参照デッキ（**本ディレクトリ配下を全件走査する**ため、2 本とも解析対象になる。中身が同一構成なので、ブランドを混ぜたくないときは `--template` でどちらかを明示する） |

参照パスはいずれも `${CLAUDE_PLUGIN_ROOT}/skills/_shared/pptx-templates/<ファイル名>`。

## ルール

- **`RONNABYTE.pptx` / `テンプレート.pptx` のファイル名は変えない**。リネーム・削除・移動をすると
  上記スキルの既定が壊れる。差し替えるときは同じファイル名のまま置き換える。
- 3 本目を増やす場合は、このファイルの選択表とエイリアス表に必ず追記する
  （表に無いファイルは「無指定時の既定」になり得ない）。
- 案件固有・クライアント固有の参照デッキはここに置かない。`pptx-from-reference/reference-decks/` へ。
- 機微情報を含む pptx をコミットしないこと。

### 本文レイアウトは「ロゴあり／なし」の 2 系統（重要）

RONNABYTE の横組みロゴは 800 の正方形マークより**幅が 2.7 倍**（アスペクト 7.31:1 / 幅 1659294 EMU）ある。
800 版は右上の余白（`x=11428248` 以降）に正方形マークを置いていたため、**同じ位置にそのまま
置き換えるとステップ表示・凡例などの右上コンテンツに重なる**。そこで本文レイアウトを 2 本に分けている。

| レイアウト | ロゴ | 使用スライド | 用途 |
|---|---|---|---|
| `1_本文` | **あり** | 25 | **新規スライドの既定**。右上が空いている前提 |
| `1_本文（ロゴなし）` | なし | 56 | 右上にコンテンツを持つ参考スライドの退避先 |
| `3_本文` | **あり** | 1 | |
| `4_本文` | **あり** | 4 | |
| `タイトルとコンテンツ` / `Title, Sub-Title and Content` | なし | 26 / 10 | 800 版でも元からロゴ無し |

ロゴ配置は RONNABYTE 本文テンプレート準拠で `off=(10243019, 181485)` / `ext=(1659294, 223024)` EMU。
**右上に図版を置くスライドを作るときは `1_本文（ロゴなし）` を選ぶこと。** `1_本文` のまま右上に
要素を置くと、レイアウト側のロゴはスライド図形の背面に回り込んで隠れる。

> 2026-10-06 の差し替え時、PowerPoint の再保存でスライドマスターが 7 本 → 1 本に統合され、
> 統合後の `1_本文` から右上ロゴが落ちた。上表の 2 系統化はその復旧として入れたもの。

## `run_image_slide` 用のセクション構造（必須）

slide_generator の `run_image_slide` は、テンプレートの**セクション構造**からスライドパターンを
カタログ化する。`ppt/presentation.xml` の `p14:sectionLst` に「`N.スライドパターン集`」という
採番付きの親セクションがあり、その枝番（`N-1.…`）配下のスライドがレイアウトの供給源になる。
**この構造が無いテンプレートを渡すと `slide_patterns=0` → 全スライドがレイアウト解決失敗で全滅する。**

**2 本とも 800 由来のため、現在はどちらも組み替え不要。** 両ファイルとも同じ構成を持つ：

```
1.オブジェクト集 / 1-1 表定義集 / 1-2 ロードマップ定義集
2.レイアウト集
3.スライドパターン集（空）                                    ← パターン親セクション
  3-1.比較表 / 3-2.箇条書き / 3-3.事例紙 / 3-4.見積書
  3-5.ステップチャート / 3-6.ロードマップ / 3-7.アジェンダ      ← 計 22 枚がパターン供給源
4. 参考スライド集
```

確認コマンド：

```bash
python3 -c "import zipfile,re;s=zipfile.ZipFile('RONNABYTE.pptx').read('ppt/presentation.xml').decode();print(re.findall(r'<p14:section[^>]*name=\"([^\"]*)\"',s))"
```

配布元の新しい RONNABYTE テンプレートで差し替える場合は、**この採番付きセクション構造を必ず再現すること**
（枝番配下にパターン見本スライドを置く）。
