# workflow.html テンプレート（チェックリスト型）

複数トラック並走型プロジェクトの初期化時、共通シェル [../assets/workflow-template.html](../assets/workflow-template.html) をプロジェクトルートに `workflow.html` としてコピーし、本ファイルの指定に従って節を埋める。

**作業状態の正本は `workflow.html` 一本**である。Markdown 版は作らない（本文一箇所ルール）。状態が変わったら HTML の該当節を Edit で直接書き換える。

## 適用条件

以下の特徴を持つプロジェクトに適用する。

- 複数のトラック（案件・テーマ・検証対象）が並走し、それぞれが独立に進む
- 各トラックはステップの順序を持ち、ステップベースで進捗管理できる
- 全体としてのマイルストーン（判断日・ローンチ目標等）が存在する
- トラックをまたぐ共通ステップ（横断資料の作成、全体の見直し判断等）がある

典型例は新規事業の営業テスト（複数社への並行アプローチ → Go/NoGo判断）。トラックが1本しかない単発調査案件には適用しない（調査型を使う）。

## 節構成（共通シェルからの差分）

| 節 | 内容 | チェックリスト型での扱い |
|----|------|----------------------|
| 1 | 基本情報・ファイル配置・連携リンク | ワークフロー類型に「チェックリスト型（カスタム）」、ワークフローソースに `custom: 本ファイル`、管理方針に「複数トラックの並走をトラック別ステップ表で管理する」と書く。トラック別ディレクトリがあればファイル配置に追記する |
| 2 | 現在の状態 | **表版に差し替える**。全体フェーズと直近マイルストーンを冒頭の箇条書きで書き、続けてトラック別の現在ステップ表を置く（下記） |
| 3 | 作業計画（WBS） | 3.1 マイルストーン／3.2 ゲート／3.3 スケジュール（ガント。レーン＝トラック）／3.4 以降に**トラック単位のステップ表**＋最後に「トラック横断」表 |
| 4 | 成果物リンク | トラックごとに行を分けて記載する |
| 5 | タスク（積み残し） | そのまま使う |
| 6 | 運用記録 | 6.1 重要な意思決定に「影響範囲」列を足し、対象トラック・ステップを書く。6.2 履歴ログはどのトラックの何がどう変わったかを1行で記録する |

節を増やす場合（TBD / 要確認事項など）は第7節として足し、TOC と `.sec-num` の連番も合わせる。

## 第2節: 現在の状態

```html
<ul class="body">
  <li>全体フェーズ: {{フェーズ名（例: 検証 → Go/NoGo判断）}}</li>
  <li>直近マイルストーン: {{YYYY-MM-DD}} — {{判断・イベントの内容}}</li>
</ul>

<table class="report-table">
  <thead>
    <tr><th>トラック</th><th>現在ステップ</th><th>ステータス</th><th>備考</th></tr>
  </thead>
  <tbody>
    <tr><td class="name">{{トラック1名}}</td><td>1.2 {{ステップ名}}</td><td>waiting_human</td><td>{{待ち先・期限}}</td></tr>
    <tr><td class="name">{{トラック2名}}</td><td>2.1 {{ステップ名}}</td><td>in_progress</td><td>—</td></tr>
  </tbody>
</table>
```

## 第3節: トラック単位のステップ表

トラックごとに小見出しと表を1つ置く。ステップ番号は `{トラック番号}.{連番}`、横断ステップは `X.{連番}` とする。

```html
<h3 class="sub-head"><span class="num">3.4</span>トラック1: {{トラック名}}</h3>

<table class="report-table">
  <thead>
    <tr><th class="num-col">WBS</th><th>ステップ</th><th>担当</th><th>ステータス</th><th>成果物</th><th>先行</th></tr>
  </thead>
  <tbody>
    <tr><td class="num">1.1</td><td class="name">{{ステップ名}}</td><td>人間</td><td>completed（{{YYYY-MM-DD}}）</td><td><code class="mono">{{パス}}</code></td><td>—</td></tr>
    <tr><td class="num">1.2</td><td class="name">{{ステップ名}}</td><td>AI</td><td><strong>not_started ← 現在</strong></td><td>{{成果物名}}</td><td>1.1</td></tr>
  </tbody>
</table>
```

最後に「トラック横断」の表を同形式で置く（`WBS` は `X.1` から）。

## 状態管理の方法

ステータスは共通語彙を使う。

| ステータス | 説明 |
|------------|------|
| `not_started` | 未着手 |
| `in_progress` | 進行中 |
| `review_pending` | AIタスク完了、ユーザーレビュー待ち |
| `waiting_human` | 人間タスク待ち（クライアント返答待ち・日程調整待ち等） |
| `completed` | 完了 |
| `skipped` | スキップ（ユーザー判断で省略） |

運用上のポイント:

- **`← 現在` マーカーはトラックごとに1つ持つ**。トラックは互いに独立して進むため、プロジェクト全体で1つではない
- 現在ステップのステータスは `<strong>` で目立たせる
- 期限があるステップはステータス欄に `not_started（期限 MM/DD）` の形で併記する
- ガント（3.3）はレーン＝トラックで組み、トラック横断ステップは最下段のレーンに置く

## PM 呼び出し時の扱い

PM は第2節の表から全トラックの現在ステップを一覧で提示し（トラック名・現在ステップ・ステータス）、どのトラックを進めるかを AskUserQuestion で選ばせる。選択後は選ばれたトラックの現在ステップに対して、SKILL.md のステータス別アクション提示に従う。直近マイルストーンが近い場合はその旨を先に示す。

## 更新ルール

1. **AIタスク実行完了時**: 該当ステップのステータスを `review_pending` に更新（第2節の表も合わせる）
2. **レビュー承認時**: `completed（YYYY-MM-DD）` に更新し、同一トラックの次ステップに `← 現在` を移動。成果物パスを表に記入
3. **人間タスク完了報告時**: `completed` に更新し、`← 現在` を移動
4. **履歴追記**: ステータス変化を第6.2節に1行で記録する（どのトラックの何がどう変わったか）
5. **意思決定**: トラックの追加・中止・方針変更は第6.1節に記録
6. **知識状態の変化時**: SKILL.md の自動同期ルールに従い `プロジェクトサマリ.md` を更新
