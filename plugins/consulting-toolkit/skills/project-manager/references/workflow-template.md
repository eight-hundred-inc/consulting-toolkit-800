# workflow.html テンプレート（調査型）

プロジェクト初期化時、共通シェル [../assets/workflow-template.html](../assets/workflow-template.html) をプロジェクトルートに `workflow.html` としてコピーし、本ファイルの指定に従って節を埋める。本ファイルは調査型（ステップ順次型）用。活動カタログ型・チェックリスト型・ポートフォリオ型は各類型のファイル（`workflow-template-{catalog|checklist|portfolio}.md`）を使う。

**作業状態の正本は `workflow.html` 一本**である。Markdown 版は作らない（本文一箇所ルール）。状態が変わったら HTML の該当節を Edit で直接書き換える。

## 共通シェルの節構成

シェルは6節を持つ。調査型では全節を使う。

| 節 | 内容 | 調査型での扱い |
|----|------|--------------|
| 1 | 基本情報・ファイル配置・連携リンク | そのまま使う。ワークフローソースに `predefined: skills/{workflow-skill}/` または `custom: 本ファイル` を書く |
| 2 | 現在の状態 | **定義リスト版を残す**（フェーズ／ステップ／ステータス／担当）。表版のコメントは削除する |
| 3 | 作業計画（WBS） | 3.1 マイルストーン／3.2 ゲート／3.3 スケジュール（ガント）／3.4 以降に**フェーズ単位の進捗表**（下記） |
| 4 | 成果物リンク | ワークフロースキルの成果物一覧から生成する |
| 5 | タスク（積み残し） | そのまま使う |
| 6 | 運用記録（重要な意思決定・履歴ログ） | そのまま使う |

## 調査型の作業計画（3.4 以降）

フェーズごとに1つの表を置く。`WBS` 列は Step 番号、`作業パッケージ` 列はステップ名とし、担当（`AI` / `人間` / `AI → SubAgent`）と連携スキルを併記する。

```html
<h3 class="sub-head"><span class="num">3.4</span>Phase 0: 提案</h3>

<table class="report-table">
  <thead>
    <tr><th class="num-col">WBS</th><th>ステップ</th><th>担当</th><th>連携スキル</th><th>成果物</th><th>状態</th></tr>
  </thead>
  <tbody>
    <tr><td class="num">Step 1</td><td class="name">論点・仮説の設計</td><td>AI</td><td>—</td><td><code class="mono">Output/論点・仮説.md</code></td><td>完了（2026-01-28）</td></tr>
    <tr><td class="num">Step 2</td><td class="name">提案書作成</td><td>AI</td><td>project-proposal（調査型）</td><td><code class="mono">Output/提案書.md</code></td><td>進行中 ← 現在</td></tr>
    <tr><td class="num">Step 3</td><td class="name">提案用スライド構成設計</td><td>AI</td><td>slide-structure-designer</td><td>—</td><td>未着手</td></tr>
  </tbody>
</table>
```

状態列の語彙は「未着手 / 進行中 ← 現在 / レビュー待ち / 人間タスク待ち / 完了（YYYY-MM-DD） / スキップ（YYYY-MM-DD）」。`← 現在` は同時に1行だけ付ける。

### 生成手順（初期化時）

1. ワークフローソースを確認する
   - 定義済み（パスA）: ワークフロースキルの SKILL.md を読み込む
   - カスタム（パスB/C）: 設計したフェーズ・ステップ定義を使う
2. フェーズ・ステップ構造を抽出し、フェーズ単位の表に展開する
3. 各ステップの担当（`AI` / `人間` / `AI → SubAgent`）を担当列に入れる
4. ワークフロー概要から連携スキル／SubAgent 名を抽出し、連携スキル列に入れる（無ければ `—`）
5. 成果物一覧から第4節「成果物リンク」を生成する
6. Step 1 の状態を `進行中 ← 現在` にする
7. ガント（3.3）は列をフェーズまたは月単位に取り、各ステップ群をバーで置く。マイルストーンは最下段の `.mrow` に ◆ で置く

## ワークフロー類型の対応

| 類型 | 対応するプロジェクト種類 | ワークフロー定義 |
|------|--------------------------|-----------------|
| 調査型 | 調査プロジェクト（下記参照） | スキル: `skills/research-project-workflow/` ＋本ファイル |
| 活動カタログ型 | 月次継続支援 | `references/workflow-template-catalog.md` |
| チェックリスト型 | 複数トラック並走案件 | `references/workflow-template-checklist.md` |
| ポートフォリオ型 | 継続クライアントエンゲージメント | `references/workflow-template-portfolio.md` |

## プロジェクト種類の説明（調査プロジェクト）

| 種類ID | 名称 | 説明 |
|--------|------|------|
| `technology-research` | 技術動向調査 | 先端技術・プレイヤー探索にフォーカス |
| `market-research` | 市場調査 | 市場規模・セグメント、競合分析にフォーカス |
| `interview-focused` | インタビュー中心 | インタビュー設計・実施が主、定性的示唆 |
| `due-diligence` | デューデリジェンス | 財務・事業・技術の深掘り、リスク評価 |

## ステータスの説明

| ステータス | 説明 | HTML の表記 |
|------------|------|------------|
| `not_started` | 未着手 | 未着手 |
| `in_progress` | 進行中 | 進行中 ← 現在 |
| `review_pending` | AIタスク完了、ユーザーレビュー待ち | レビュー待ち |
| `waiting_human` | 人間タスク待ち | 人間タスク待ち |
| `completed` | 完了 | 完了（YYYY-MM-DD） |
| `skipped` | スキップ（ユーザー判断で省略） | スキップ（YYYY-MM-DD） |

第2節「現在の状態」のステータスは上記の英語語彙をそのまま書く（PM の自動ルーティングが読む）。第3節の表では日本語表記を使う。

## 更新ルール

### 進捗管理

1. **AIタスク実行完了時**: 第2節のステータスを `review_pending` に更新（表の状態はまだ「完了」にしない）
2. **レビュー承認時**: 表の状態を「完了（YYYY-MM-DD）」に、`← 現在` を次のステップへ移し、第2節を次ステップ・`not_started` に更新
3. **レビューでスキップ時**: 表の状態を「スキップ（YYYY-MM-DD）」にし、次のステップへ進む
4. **成果物作成時**: 第4節の成果物リンクを更新
5. **履歴追記**: 第6.2節に1行追記する（レビュー結果も記録）

### 知識状態の管理

論点・仮説・アプローチの検証状況は `プロジェクトサマリ.md` で管理する（`workflow.html` には持たない）。`workflow.html` はプロセス進捗と意思決定の記録に専念する。

| セクション | 管理先 | 更新契機 |
|-----------|--------|---------|
| 論点・仮説の検証状況 | プロジェクトサマリ.md | 論点・仮説に変化があった場合 |
| 重要な意思決定 | workflow.html 第6.1節（追記型） | スコープ変更・方針転換時 |
| プロセス進捗 | workflow.html 第2・3節 | ステップの状態変化時 |

### HTML 編集の実務

- 更新は Edit の文字列置換で行う。表の行追加は直前の `</tr>` を目印に挿入する
- 節を増減したら第2節冒頭の TOC（`.toc-list`）と `.sec-num` の連番も合わせる
- 検証は変更した節だけを `screenshot.py --selector "#sec-N"` で確認する。全面レンダリングは節を増やしたときだけ行う
- 新規 CSS を `<style>` に足さない。配色は `--accent` / `--ink` / `--rule` 等の既存変数のみを使う（ガント用の `.fig-wbs` はシェルに同梱済み）

## CLAUDE.md との役割分担

プロジェクトの状態を3ファイルで管理する。`CLAUDE.md` は静的な基本情報、`workflow.html` はプロセス進捗、`プロジェクトサマリ.md` は知識状態（論点・仮説・リスク等）を担う。

| 情報 | 管理先 |
|------|-------|
| クライアント名・納期・スコープ | CLAUDE.md（静的） |
| 作業上の注意・文書作成ガイドライン | CLAUDE.md（静的） |
| 論点・仮説の検証状況・リスク | プロジェクトサマリ.md |
| ファイル配置 | workflow.html |
| 重要な意思決定 | workflow.html |
| 現在のステップ・作業計画 | workflow.html |
| 成果物リンク | workflow.html |
| 履歴ログ | workflow.html |

## 既存プロジェクトの扱い（後方互換）

`workflow.md` を持つ既存プロジェクトは、そのまま `workflow.md` を正本として運用する。HTML への変換はユーザーの指示があったときだけ行い、初期化フロー以外で自動移行はしない。変換するときは、`workflow.md` の全節（基本情報・ファイル配置・連携リンク・現在の状態・進捗・成果物リンク・タスク・意思決定・履歴）を HTML の対応節へ移し、移行完了を第6.2節に1行記録してから `workflow.md` を削除する。
